## 👋 About me

I'm **S. Amir Reza Davarzani**, a front-end-focused full-stack developer who enjoys building software at the point where **product design, application architecture, backend contracts, and delivery engineering** meet.

My strongest work usually starts with a complex system — AI conversations, authentication flows, internal dashboards, booking and payment rules, workflow engines, or operational tooling — and turns it into something that feels **clear, fast, reliable, and maintainable**.

I care about more than getting a page to render. I care about the system behind it: state boundaries, data contracts, failure modes, transaction safety, accessibility, performance, testing, deployment, and what the next developer will experience six months later.

> **My favorite kind of engineering:** making complicated systems feel simple without pretending the complexity does not exist.

## 🔒 Some of my strongest work is private

Not everything worth building belongs in a public repository.

A meaningful part of my recent engineering work lives in **private repositories or organization-owned codebases**: enterprise applications, AI-assisted products, workflow and form engines, internal operational systems, and architecture/platform foundations.

Those projects involve the kind of work that does not always show up in public contribution graphs: defining technical baselines, designing module boundaries, shaping API contracts, coordinating gated delivery, hardening authentication and infrastructure, reviewing changes, and moving systems from “it works” toward “it is ready to live with.”

**I keep private code private.** When appropriate, I can still discuss the architecture, engineering decisions, trade-offs, and my responsibilities without exposing confidential implementation details.

## 🧠 How I like to engineer

- **Product first, not screenshot first.** UI quality includes states, edge cases, loading, failure, empty data, mobile behavior, accessibility, and the backend contract behind the screen.
- **Correctness before cleverness.** Transactions, invariants, validation, idempotency, authorization, and predictable failure modes matter.
- **Architecture should reduce future cost.** I like explicit boundaries, ADRs, service layers, reusable primitives, and boring solutions where boring is better.
- **Testing is part of implementation.** I prefer changes that arrive with the checks needed to keep them safe.
- **Git history is an engineering interface.** Small branches, focused commits, PR review, CI, and documented decisions make teams faster.
- **Design and engineering are not enemies.** The best interfaces can be visually polished and technically disciplined at the same time.
